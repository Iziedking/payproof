What the texts settle:

- **D1:** closed. The Fourth Schedule bands, read from the Act itself (page A540), are the six
  bands in PLAN section 6.
- **D11:** closed for the text. The State Council policy library copy of Announcement 2023 No. 30
  was read (not chinatax.gov.cn). It runs to 2027-12-31 and gives no rounding rule, so D12
  stays open.
- **D3:** narrowed, not closed. Section 162 (1) (t) exempts employment income where the person
  "earns gross income of national minimum wage or less". That supports a test on gross pay, at
  or below the minimum wage. Whether the test is monthly or annual is still open. The minimum
  wage figure (N70,000 a month) is not yet read from an official text.

## 3. Rule packs (task `p1-vectors`)

- `rules/ng-paye-nta2025/`, `rules/cn-bonus-2023-30/` and `rules/split-v1/` each have a
  `README.md` (the reading, its sources and open points), a `layout.json` and a `vectors.json`.
- `scripts/p1/make_vectors.py` derives the vectors with plain integer arithmetic, written apart
  from the P0 checker. Every vector says `"source": "derived"` and why it was chosen: each band
  or bracket edge with plus and minus one, the minimum-wage edge, the rent-relief cap, each
  deduction alone, invalid inputs, and the largest values the fields hold.
- Counts: 32, 22 and 23. No vector is from an official worked example yet; the READMEs say so.
- The script also asserts the figures quoted in the READMEs: N840,001 pays N6,000; 36,000 yuan
  pays 1,080 yuan; 36,001 yuan takes home less than 36,000 yuan; and the split example pays
  212,500. All passed.

## 4. Compiler core (task `p1-compiler-test`)

`compiler/src/netlist.ts` (decode, encode, load with the well-formedness checks, one beat,
`evaluate`, bit packing) and `compiler/src/layout.ts` (field `pack` and `unpack`). They are
written from the TAP-02 reference implementation, are TypeScript with no dependencies, and run
by Node 24.22.1 directly.

`node --test`, 26 tests, **26 passed** (two runs, 1.46 s and 1.86 s; the second is saved as `docs/evidence/p1/compiler-test.log`):

- The vectors file's SHA-256 is the one TAP-02 names.
- All 5 valid circuits: decode then encode returns the same bytes; truth tables and beats
  (state and outputs) match, including LATCH and REF with state.
- All 8 ill-formed netlists are refused with the reference's own reason.
- The packing edge cases and the NAND truth table pass.
- For each rule, the layout matches the P0 netlist, and every rule vector runs through
  `pack`, `evaluate` and `unpack` with the expected outputs. That is 32 vectors on `ng_paye`
  (8,482 gates), 22 on `cn_bonus` (3,573) and 23 on `split_check_modc_32` (41,128). The
  vectors come from separate Python arithmetic, so this also checks the netlists against the
  readings.
- 200 random pack/unpack round trips per layout, and refusal of values that do not fit or
  fields that overlap.

The files tested were compared by SHA-256 with the local copies after the run: identical.

## 5. Yosys import, export, prover runs and the trap finder (task `p1-engine-test`)

**Tools set up for P1.**

- host-service: Yosys 0.70 (YoWASP wheel, `scripts/p0/setup-yosys.sh`, wheel SHA-256 checked;
  task `p1-setup-yosys`), workdir `/tmp/izie-build-test.9K1ZmFN3`.
- node-services: OSS CAD Suite 2026-10-29 (Yosys 0.70+277 with native `yosys-abc`), installed
  by `scripts/p1/setup-oss-cad-suite.py` (task `p1-setup-oss-cad-suite`). The archive's
  747,289,273 bytes matched SHA-256 `ae6f7f11…15eb` from the GitHub release API before it was
  unpacked.
- The tests themselves ran in node 24.22.1 with no network.

**Fresh synthesis** (task `p1-synth-wage`, host-service): `adder8`, `cn_bonus`, `ng_paye`,
`ng_paye_mutant19` and `split_check` at 8, 12 and 16 bits. The gate counts are identical to P0
(90; 3,520; 8,437; 8,597; 3,979; 7,137; 11,168). The Yosys JSON was relayed to node-services and
the SHA-256 of all 7 files matched on both hosts.

**New code.**

- `compiler/src/yosys.ts`, `fromYosys`: a port of the P0 converter `scripts/p0/yosys2tap.py`.
- `prover/src/export.ts`, `toVerilog`: TAP-02 bytes to structural Verilog, one NAND per record,
  each REF target as its own module.
- `prover/src/run.ts`, `equivalent`: Yosys `miter -equiv -flatten`, then ABC `&cec -m`, taking
  the last verdict line and parsing the counterexample.
- `prover/src/traps.ts`, `findTraps`: the P0 bonus-trap method, with ABC `iprove` for edges,
  binary-search widening, replay in the simulator, and a final "none left" query.

**Results.** Compiler: 33 of 33 passed (`docs/evidence/p1/engine/compiler-test.log`). These are
the 26 tests of section 4 and 7 new ones:

- `fromYosys` gives **byte for byte the same netlists** as the P0 tape-out files for `adder8`,
  `cn_bonus` and `ng_paye`.
- The rule vectors pass through the freshly imported `cn_bonus` and `ng_paye`. The 19% mutant
  of `ng_paye` differs on at least one vector.
- `split_check_8` matches the rule on all of 3,000 inputs.

Prover: 8 of 8 passed on the second run (`docs/evidence/p1/engine/prover-test.log`):

| Test | Result |
| --- | --- |
| Round trip `adder8`: bytes, export, re-synthesis, import | 90 gates, then 90; same outputs on 500 random inputs; ABC: equivalent, 0.05 s |

The first prover run (`prover-test-run1.log`) had 5 of 7 passing. Its two failures were in the
test, not the prover. The test rewired a fixed gate, a third of the way in, and in `cn_bonus`
(NAND 1,191) and `split_check_8` (NAND 1,326) that gate turned out redundant: ABC proved each
mutant equal to the original. So those pairs were not known-different. The test now picks the
first gate whose rewiring shows a difference in the simulator, then requires the solver to
agree. The trap finder test was added for the second run, with one fix to its widening query
(a constant written as a bit-select, which Verilog does not allow).

Yosys warns "Treating undriven bit miter.\in_in [i] like $anyseq" for each input bit when it
writes the miter AIG. The inputs stay free, so an equality check is not weakened. All three
counterexamples replayed with input bit i read as `in[i]`. This is noted, not yet explained.

All 7 source and test files tested were compared by SHA-256 with the local copies: identical.
