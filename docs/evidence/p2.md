# P2 evidence: the three rules on chain

P2 started 2026-11-21 (re-planned target Nov 24 to Nov 26). The app pages of P2 are built by
the design session in `app/`; this file covers the circuits and the tape-out.

## 1. split-v1 as REF modules

TAP-02 section 3 allows a REF target at most 255 inputs and 255 outputs, and PLAN L17 says
rules are built from modules joined with REF. Of the joined check circuit's modules, `m_cmp`
has 299 inputs (shares, total, lhs, lhs1, rhs), so it cannot be a REF target. Every other
module can.

`scripts/p0/synth-all.sh`, function `synth_modc`, now also writes
`out/split_check_modc_32.ref.json` in the same Yosys session. Every module except `m_cmp` keeps
its own netlist (`keep_hierarchy`, so `flatten` leaves it alone), and `m_cmp` is flattened into
the top. `design -save` / `design -load` then restore the joined design. The flat netlist is
built as before: same `same-*` comparisons, and the same counts (41,128 gates: 28,467 NAND,
12,661 NOT). Run `p2-synth-check-ref`, host-service.

`compiler/src/yosys.ts` now emits a REF record for an instance of a module that is already on
chain. Its outputs are unchanged for netlists without instances: the 33 compiler tests,
including byte identity with the P0 tape-out files, and the 8 prover tests pass again (run
`p1-engine-test`, 2026-11-21).

| Piece | Input / output bits | NAND records | Bytes |
| --- | --- | --- | --- |
| `m_mul_tmc_32` (used twice) | 64 / 64 | 14,969 | 104,783 |
| `m_x8500` | 64 / 78 | 3,630 | 25,410 |
| `m_add` | 124 / 79 | 804 | 5,628 |
| `m_x10000_narrow` | 32 / 46 | 1,635 | 11,445 |
| `m_x10000_wide` | 64 / 78 | 3,318 | 23,226 |
| Top: `m_cmp` inline plus 6 REF records | 128 / 1 | 1,833 | 14,253 |

A module's record count can be a few gates above its Yosys cell count. The converter adds a
buffer where an output bit is not driven by a gate it can move to the end (for example
`m_x8500`: 3,624 cells, 3,630 records). On chain, `circuitInfo` of the top reports 41,158
gates in all. Transistors burned for split-v1: 26,189, because the multiplier is taped out
once and used twice.

## 3. What the real tape-out needs (not done yet)

- **Signing route.** `cast send` 1.8.6 takes calldata only on the command line (`--data <hex>`
  or a signature with arguments; read from `cast send --help` in the pinned image,
  2026-11-21). A Windows command line stops at 32,767 characters. Only `m_add` (11,530
  characters of calldata) and `m_x10000_narrow` (23,178) fit. The top (28,810) is close to the
  limit. The rest do not fit: the multiplier needs 209,866 characters.
- **Transaction size.** The multiplier's tape-out carries 104,783 bytes of netlist. Whether X
  Layer's transaction pool accepts a transaction that large is not verified; the fork does
  not check it.
- **Funds.** The deployer held 0.020266 OKB after P0. The eight decision tape-outs cost about
  0.0130 OKB, leaving about 0.0072 OKB. The explanation and validity circuits, and a real
  split-v1 `eval` transaction (about 0.0019 OKB), are not yet counted. Transistors are not a
  limit: 38,244 of 9,999,910 would be burned.
