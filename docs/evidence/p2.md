# P2 evidence: the three rules on chain

P2 started 2026-11-21 (re-planned target Nov 24 to Nov 26). The app pages of P2 are built by
the design session in `app/`; this file covers the circuits and the tape-out.

## 1. split-v1 as REF modules

TAP-02 section 3 allows a REF target at most 255 inputs and 255 outputs, and PLAN L17 says
rules are built from modules joined with REF. Of the joined check circuit's modules, `m_cmp`
has 299 inputs (shares, total, lhs, lhs1, rhs), so it cannot be a REF target. Every other
module can.

`scripts/p0/synth-all.sh`, function `synth_modc`, now also writes
`out/split_check_modc_32.ref.json` in the same Yosys session. Every module except `m_cmp` keeps
its own netlist (`keep_hierarchy`, so `flatten` leaves it alone), and `m_cmp` is flattened into
the top. `design -save` / `design -load` then restore the joined design. The flat netlist is
built as before: same `same-*` comparisons, and the same counts (41,128 gates: 28,467 NAND,
12,661 NOT). Run `p2-synth-check-ref`, host-service.

`compiler/src/yosys.ts` now emits a REF record for an instance of a module that is already on
chain. Its outputs are unchanged for netlists without instances: the 33 compiler tests,
including byte identity with the P0 tape-out files, and the 8 prover tests pass again (run
`p1-engine-test`, 2026-11-21).

| Piece | Input / output bits | NAND records | Bytes |
| --- | --- | --- | --- |
| `m_mul_tmc_32` (used twice) | 64 / 64 | 14,969 | 104,783 |
| `m_x8500` | 64 / 78 | 3,630 | 25,410 |
| `m_add` | 124 / 79 | 804 | 5,628 |
| `m_x10000_narrow` | 32 / 46 | 1,635 | 11,445 |
| `m_x10000_wide` | 64 / 78 | 3,318 | 23,226 |
| Top: `m_cmp` inline plus 6 REF records | 128 / 1 | 1,833 | 14,253 |

A module's record count can be a few gates above its Yosys cell count. The converter adds a
buffer where an output bit is not driven by a gate it can move to the end (for example
`m_x8500`: 3,624 cells, 3,630 records). On chain, `circuitInfo` of the top reports 41,158
gates in all. Transistors burned for split-v1: 26,189, because the multiplier is taped out
once and used twice.

## 3. The signing route: a Foundry script that reads the netlist from a file

`cast send` 1.8.6 takes calldata only on the command line (`--data <hex>` or a signature with
arguments; read from `cast send --help` in the pinned image, 2026-11-21). A Windows command line
stops at 32,767 characters. Only `m_add` (11,530 characters of calldata) and `m_x10000_narrow`
(23,178) would fit; the multiplier needs 209,866. The owner approved a Foundry script instead
(2026-11-22).

**What it is.** `chain/script/TapeOut.s.sol`, run with `forge script` from `chain/`. It reads one
netlist file with `vm.readFileBinary` and calls `tapeout(bytes,uint32,uint32)` with the fee. It
holds no key: the owner signs with their keystore account (`--account payproof-deployer`).
Before it builds the transaction it requires chain id 196, a file of 1 to 131,072 bytes, the
keccak-256 given on the command line (from `chain/netlists/manifest.json`), and a tape-out fee of
exactly 0.0013 OKB. `chain/foundry.toml` lets it read only `./netlists`. It imports nothing, so
forge-std is not downloaded; forge downloads solc 0.8.28.

Sources, read 2026-11-22: the `forge script` flags from `--help` of the pinned Foundry 1.8.6
image (`docs/evidence/p2/tools/forge-script-help-1.8.6.txt`; the docs page returned 404); the
cheatcode address and `readFileBinary` from forge-std `src/Base.sol` and `src/Vm.sol`;
`startBroadcast` and `stopBroadcast` from getfoundry.sh/cheatcodes. The `fs_permissions` syntax
was not found in the docs pages read; the dry run below shows it works.

**Helper.** `scripts/p2/tapeout-plan.mts` holds no key and sends nothing. `prepare` writes the
netlist files and the manifest (the split-v1 top only once the five module ids are in
`ids.json`, because its REF records name them). `command` prints the owner's forge line with the
live gas price. `landed` checks a landed transaction (status, the exact netlist bytes sent, the
new circuit id, `circuitInfo` gates) and records the id. `check` compares on-chain `eval` with
the local simulator.

**Committed netlists.** `chain/netlists/` holds the seven pieces that do not depend on circuit
ids (five modules, cn-bonus, ng-paye) and their manifest. They are the same bytes as the fork
tape-outs in section 2.

## 4. What the real tape-out still needs

- **The owner's forge.** The dry run used forge 1.8.6. The owner's PC had Foundry 1.7.1 in P0.
  Installing 1.8.6 (`foundryup --install v1.8.6`) runs the same version as the dry run.
- **Transaction size.** The multiplier's tape-out carries 104,783 bytes of netlist. Whether X
  Layer's transaction pool accepts a transaction that large is not verified; the fork does
  not check it.
- **Funds.** The deployer held 0.020266 OKB after P0. The eight decision tape-outs cost about
  0.0130 OKB, leaving about 0.0072 OKB. The explanation and validity circuits, and a real
  split-v1 `eval` transaction (about 0.0019 OKB), are not yet counted. Transistors are not a
  limit: 38,244 of 9,999,910 would be burned.
